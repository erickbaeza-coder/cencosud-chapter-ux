Módulo 1: Qué es un LLM y cómo funciona Claude

Un Large Language Model, o LLM, es un tipo de inteligencia artificial entrenado con enormes cantidades de texto. Aprende patrones del lenguaje para poder generar, analizar y transformar texto de forma coherente. Claude, desarrollado por Anthropic, es el LLM que usamos como herramienta principal en el Chapter UX de Cencosud.

A diferencia de un buscador, Claude no busca información en internet en tiempo real. Trabaja con lo que aprendió durante su entrenamiento y con el contexto que tú le das en cada conversación. Por eso, la calidad de lo que le entregues determina la calidad de lo que recibes.

Concepto clave: Claude no "sabe" cosas como un humano. Predice la siguiente palabra más probable basándose en patrones estadísticos. Por eso es excelente para estructurar, redactar y analizar, pero siempre debes validar su output.

Módulo 2: Chat, Cowork y Claude Code

Claude se puede usar de tres formas principales. Chat es la interfaz conversacional más simple: escribes, Claude responde. Es ideal para preguntas rápidas, brainstorming o redacción de textos cortos.

Cowork es el modo avanzado en la app de escritorio. Permite trabajar con archivos de tu computador, ejecutar skills y plugins, conectar herramientas externas via MCP, y automatizar flujos complejos. Es el entorno principal que usamos en el Chapter UX.

Claude Code es la interfaz de línea de comandos para desarrolladores. Los UX Designers no necesitan usarla directamente, pero es útil saber que existe porque algunos plugins y MCPs se configuran desde ahí.

Módulo 3: Tu primera skill

Una skill es un conjunto empaquetado de instrucciones que Claude ejecuta para una tarea específica. En vez de escribir un prompt largo cada vez que necesitas algo, instalas una skill que ya tiene la estructura, el tono y los criterios validados por el equipo.

Para instalar tu primera skill, abre Cowork, ve a Settings, busca la skill en el catálogo del Chapter y haz clic en Install. Una vez instalada, simplemente escribe el nombre de la skill o describe lo que necesitas y Claude la activará automáticamente.

Ejemplo práctico: Con la skill "UX Jira Ticket Writer" puedes decirle a Claude "crea un ticket para el flujo de checkout de Jumbo" y te genera un ticket estructurado con criterios de aceptación, sin necesidad de recordar el formato.

Módulo 4: Prompting básico

Un prompt es la instrucción que le das a Claude. La estructura básica de un buen prompt tiene tres partes: contexto (quién eres, en qué proyecto trabajas), instrucción (qué necesitas) y formato (cómo quieres el resultado).

Por ejemplo, en vez de decir "hazme un journey map", un mejor prompt sería: "Soy Product Designer del equipo Whitelabel, trabajando en el flujo de checkout mobile para Jumbo Chile. Necesito un journey map del usuario desde que agrega el último producto al carro hasta que recibe confirmación de compra. Formato: tabla con columnas Etapa, Acción, Emoción, Pain Point, Oportunidad."

Módulo 5: Glosario esencial

Antes de profundizar en herramientas más avanzadas, es fundamental manejar el vocabulario básico. Los términos que más usarás son: LLM (el modelo de lenguaje), Prompt (tu instrucción), Token (la unidad de texto que procesa el modelo), Skill (instrucciones empaquetadas), Plugin (conjunto de skills), MCP (protocolo para conectar herramientas externas) y Cowork (el entorno de escritorio donde trabajamos).

Todos estos términos están explicados en detalle en la sección de Glosario más abajo. Te recomendamos revisarla como referencia cada vez que encuentres un concepto nuevo.

Módulo 1: El catálogo de skills del Chapter

El Chapter UX de Cencosud mantiene un catálogo centralizado de skills y plugins validados. Cada herramienta del catálogo fue creada para resolver un problema recurrente del equipo: generar tickets de Jira con formato estándar, documentar componentes UI, corregir propiedades de diseño o crear usuarios sintéticos para testing.

La regla de oro es: si existe una skill para lo que necesitas, úsala antes de escribir un prompt desde cero. Las skills ya tienen los criterios del Chapter incorporados y producen resultados consistentes entre equipos.

Módulo 2: Plugins Discovery y Prisma Designer

Los dos plugins principales del Chapter son Discovery Agéntico (v2.15.0) y Prisma Designer (v3.1.0). Discovery Agéntico contiene 9 skills que cubren todo el proceso de Discovery en 6 pasos (S1 a S6) y Diseño en 3 pasos (DS1 a DS3). Prisma Designer tiene 5 skills enfocadas en trabajar con el Design System Prisma: sincronizar componentes, validar JSON, crear pantallas en Figma, pasar el Quality Gate y resolver nombres de componentes.

Estos plugins se instalan una vez y están disponibles en todas tus conversaciones de Cowork. Cuando dices "iniciar discovery" o "ejecutar S1", Claude activa automáticamente la skill correspondiente.

Diferencia clave: Un plugin agrupa múltiples skills bajo un mismo nombre. Instalas el plugin una vez y accedes a todas sus skills. Una skill individual se instala por separado y resuelve una tarea específica.

Módulo 3: Conectar MCPs

MCP significa Model Context Protocol. Es el estándar que permite a Claude conectarse con herramientas externas como Figma, Jira, Confluence o SharePoint. Cuando conectas un MCP, Claude puede leer y escribir directamente en esa herramienta sin que tú tengas que copiar y pegar información.

Los MCPs más relevantes para el Chapter son: Figma MCP (para leer diseños y crear pantallas), Prisma MCP (para acceder al catálogo de componentes del Design System), y Jira + Confluence MCP (para gestionar tickets y documentación). Las guías de conexión paso a paso están en la sección de Guías MCP de esta misma página.

Módulo 4: Prompting avanzado

Más allá del prompt básico, hay técnicas que mejoran significativamente los resultados. Few-shot prompting consiste en darle a Claude ejemplos concretos del output que esperas antes de pedirle que genere el suyo. Chain-of-thought le pide que razone paso a paso antes de dar una respuesta final.

Para UX, el prompting avanzado es especialmente útil cuando necesitas análisis complejos: "Analiza este flujo de checkout paso a paso. Para cada pantalla, identifica: qué decisión toma el usuario, qué información necesita, qué puede salir mal, y qué oportunidad de mejora existe. Muestra tu razonamiento antes de la conclusión."

Módulo 5: Buenas prácticas por perfil

Cada perfil UX tiene sus propios casos de uso óptimos con IA. Product Design se beneficia más de Discovery Agéntico, generación de tickets y journey maps. UI se beneficia de Prisma Designer, validación de componentes y generación de pantallas. Research puede usar IA para sintetizar entrevistas, generar guías de investigación y analizar datos cualitativos. Content puede generar copy, validar tono de voz y crear variantes de microcopy.

La clave para todos los perfiles: Claude es un asistente que amplifica tu expertise, no un reemplazo. El juicio de diseño, la empatía con el usuario y el conocimiento del negocio siguen siendo tu responsabilidad.

Módulo 1: Discovery Agéntico completo (S1→S6)

El Discovery Agéntico es un proceso de 6 pasos donde Claude actúa como agente para ejecutar un UX Discovery de principio a fin. S1 (Product Strategy) define el contexto estratégico del producto. S2 (Market Trends) investiga competidores y tendencias del mercado. S3 (User Needs) sintetiza necesidades de usuarios a partir de research existente.

S4 (User Journey) mapea el journey actual con fricciones y momentos de verdad. S5 (Business Value) cuantifica el impacto de negocio y construye el business case. S6 (PDR Synthesizer) consolida todo en un Product Design Requirements, el documento que alimenta la fase de diseño.

El Discovery Agéntico no reemplaza el research con usuarios reales. Acelera la síntesis y estructuración del conocimiento existente, permitiéndote llegar más preparado a las sesiones de investigación con datos secundarios ya procesados.

Módulo 2: Diseño Agéntico (DS1→DS3) + Figma

El Diseño Agéntico toma el PDR del Discovery y lo transforma en diseño concreto en 3 pasos. DS1 (Wireframe Viability) genera un brief de wireframe, inventario de pantallas y análisis de viabilidad del diseño. DS2 (Wireframe Generator) produce wireframes HTML navegables que puedes revisar en el navegador.

DS3 (Design Directions) genera 3 opciones de diseño en formato JSON estructurado, cada una con una dirección visual distinta. Este DS3 JSON es el puente hacia Figma: usando Prisma Designer, se convierte directamente en pantallas de alta fidelidad con componentes reales del Design System Prisma.

Módulo 3: Crear una skill desde cero

Si identificas una tarea que tu equipo repite frecuentemente y no existe una skill para ella, puedes crear la tuya. Una skill es esencialmente un archivo SKILL.md con instrucciones estructuradas que Claude sigue cada vez que se activa.

El proceso es: definir el trigger (cuándo se activa la skill), escribir las instrucciones paso a paso, definir los inputs que necesita del usuario, especificar el formato de output, y testear con casos reales. El Skill Creator en el catálogo puede ayudarte a construirla con asistencia guiada.

Módulo 4: Quality Gate y Gold Standard

El Quality Gate evalúa la calidad de un diseño en 6 dimensiones con un scoring de 100 puntos: adherencia al Design System Prisma, accesibilidad, consistencia interna, jerarquía visual, usabilidad y completitud del flujo. Un diseño debe alcanzar al menos 80 puntos para considerarse listo para handoff a desarrollo.

El Gold Standard es el nivel de calidad que define el Chapter como referencia. Incluye los criterios del Quality Gate más consideraciones de negocio específicas de cada bandera y dominio. Es la vara con la que medimos si un diseño está listo para producción.

Módulo 5: Prisma MCP — sync, validación y creación

Prisma MCP es el servidor que conecta Claude con el catálogo completo de componentes del Design System Prisma. Sus capacidades principales son: sincronizar la librería de componentes desde Figma (sync), validar que un DS3 JSON use componentes correctos con propiedades válidas (validar), y crear pantallas completas en Figma a partir de un DS3 JSON (crear).

El flujo típico es: generas un DS3 JSON en el paso DS3 del Diseño Agéntico, lo validas contra el catálogo de Prisma para detectar errores antes de crear, y finalmente lo envías a Figma donde Prisma Designer lo convierte en pantallas con componentes reales, grids, scroll y elementos sticky correctamente configurados.

Tip avanzado: Antes de crear pantallas, siempre ejecuta /sync-prisma para asegurarte de tener la versión más actualizada del catálogo de componentes. Luego /validar-ds3 para detectar errores. Solo después /crear-pantallas.

Glosario IA para UX

Conceptos clave de IA explicados para el Chapter UX. Busca por término o navega por categoría.

LLM Fundamento

Large Language Model. Modelo de inteligencia artificial entrenado con grandes volúmenes de texto que puede generar, analizar y transformar lenguaje natural. Claude es un LLM de Anthropic.

Prompt Fundamento

Instrucción o texto que le das al modelo para que genere una respuesta. La calidad del prompt determina la calidad del output. Incluye contexto, instrucciones y formato esperado.

Skill Organización

Conjunto empaquetado de instrucciones que Claude ejecuta para una tarea específica. Ejemplo: UX Jira Ticket Writer genera tickets estructurados. Se instalan en Cowork o Claude Code.

Plugin Organización

Paquete que agrupa múltiples skills, MCPs y herramientas bajo un mismo nombre. Ejemplo: Discovery Agéntico (9 skills) o Prisma Designer (5 skills). Se instalan como unidad.

MCP Integración

Model Context Protocol. Estándar abierto que permite a Claude conectarse con herramientas externas (Figma, Jira, SharePoint). Cada MCP expone capacidades que Claude puede usar.

Cowork Herramienta

Modo de Claude en la app de escritorio para tareas complejas con archivos, navegación y herramientas. Permite usar skills, plugins y MCPs. Es el entorno principal para diseñadores.

Discovery Agéntico Proceso

Proceso de 6 pasos (S1-S6) donde Claude actúa como agente para ejecutar un UX Discovery completo: estrategia, mercado, usuarios, journey, business value y PDR.

PDR Proceso

Product Design Requirements. Documento que sintetiza todo el Discovery en requerimientos accionables para diseño. Es el output del paso S6 y el input del Diseño Agéntico.

DS3 JSON Creación

Formato JSON estructurado que describe pantallas con componentes Prisma. Es el output del paso DS3 (Design Directions) y el input de Prisma Designer para crear en Figma.

Quality Gate Creación

Evaluación de calidad de diseño en 6 dimensiones con scoring de 100 puntos. Verifica adherencia a Prisma, accesibilidad, consistencia y mejores prácticas antes del handoff.

Token Fundamento

Unidad mínima de texto que procesa un LLM (aproximadamente ¾ de una palabra). La ventana de contexto de Claude define cuántos tokens puede manejar en una conversación.

Prisma Sistema

Sistema de diseño unificado de Cencosud para las 14 banderas. Define componentes, tokens (colores, spacing, tipografía) y reglas de diseño que se aplican vía IA con Prisma Designer.

Buenas prácticas

Tips y patrones validados por el equipo para sacar el máximo provecho de las herramientas IA.

Da contexto antes de pedir

Siempre empieza con el contexto del flujo, la bandera, el dominio y el perfil de usuario antes de pedir que genere algo. Claude trabaja mejor cuando entiende el "por qué".

Usa skills antes que prompts libres

Las skills del catálogo ya tienen la estructura, el tono y los criterios validados por el Chapter. Úsalas como punto de partida, no reinventes la rueda con prompts genéricos.

Revisa siempre el output

Claude es un asistente, no un reemplazo. Revisa cada output contra tu criterio de diseño, el DS Prisma y el contexto del negocio. El Quality Gate ayuda pero no sustituye tu juicio.

No compartas datos sensibles

No incluyas datos personales de usuarios reales, credenciales, tokens de API ni información financiera en las conversaciones con Claude. Usa datos ficticios o anonimizados.

Guías de conexión MCP

Paso a paso para conectar las herramientas externas que potencian el trabajo con Claude.

Fácil

Figma MCP

Lee y escribe diseños en Figma directamente desde Claude.

  1. Ir a Figma → Settings → Security → Personal Access Tokens
  2. Crear token con permisos de lectura y escritura
  3. En Claude, conectar el MCP de Figma desde Settings
  4. Verificar conexión con "whoami" en el chat
Medio

Prisma MCP

Accede al catálogo de componentes Prisma, valida DS3 y crea pantallas.

  1. Clonar el repo prisma-mcp y ejecutar npm install
  2. Configurar FIGMA_TOKEN en variables de entorno (opcional para sync)
  3. Registrar en ~/.claude/mcp_settings.json
  4. Verificar con "list_prisma_components" en el chat
Fácil

Jira + Confluence MCP

Lee y crea tickets en Jira, busca y edita páginas en Confluence.

  1. En Claude, ir a Settings → Connectors
  2. Buscar "Atlassian" y hacer clic en Connect
  3. Autorizar con tu cuenta Cencosud de Atlassian
  4. Verificar con una búsqueda de tickets en el chat
