Discovery Agéntico — S1 a S6

Cada paso se ejecuta como una skill independiente en Cowork. El output de cada paso alimenta el siguiente.

S1
Estrategia

Product Strategy

Define el contexto estratégico del producto: qué problema resuelve, para quién, en qué dominio y bandera opera, y cuáles son los objetivos de negocio. Es el input que alinea todo el resto del Discovery.

Inputs
  • Dominio y bandera
  • Problema a resolver
  • Objetivos de negocio
Outputs
  • Strategy Brief
  • Scope definido
  • Métricas de éxito
$ejecutar S1
S2
Investigación

Market Trends

Investiga el mercado, competidores directos e indirectos, tendencias de la industria y benchmarks de UX. Genera un análisis comparativo estructurado.

Inputs
  • Strategy Brief (S1)
  • Competidores conocidos
Outputs
  • Benchmark competitivo
  • Tendencias de mercado
  • Oportunidades detectadas
$ejecutar S2
S3
Usuarios

User Needs

Sintetiza necesidades de usuarios a partir de research existente: entrevistas, surveys, analytics, tickets de soporte. Genera personas, pain points y oportunidades priorizadas.

Inputs
  • Research existente (entrevistas, surveys)
  • Data de analytics
  • Market Trends (S2)
Outputs
  • Personas sintetizadas
  • Pain points priorizados
  • Necesidades funcionales
$ejecutar S3
S4
Journey

User Journey

Mapea el journey actual del usuario paso a paso: acciones, emociones, fricciones y momentos de verdad. Identifica dónde intervenir con la mayor oportunidad de impacto.

Inputs
  • Personas y pain points (S3)
  • Flujo actual del producto
Outputs
  • Journey Map completo
  • Momentos de verdad
  • Oportunidades de diseño
$ejecutar S4
S5
Negocio

Business Value

Cuantifica el impacto de negocio de las oportunidades detectadas. Construye el business case con métricas, ROI estimado y priorización por valor.

Inputs
  • Journey y oportunidades (S4)
  • Métricas de negocio actuales
Outputs
  • Business case
  • ROI estimado
  • Priorización por impacto
$ejecutar S5
S6
Síntesis

PDR Synthesizer

Consolida todo el Discovery en un Product Design Requirements: el documento maestro que sintetiza estrategia, mercado, usuarios, journey y business value en requerimientos accionables para diseño.

Inputs
  • Outputs de S1 a S5
Outputs
  • PDR completo (.md)
  • Requerimientos priorizados
  • Input para DS1
$ejecutar S6
PDR conecta Discovery → Diseño Agéntico

Diseño Agéntico — DS1 a DS3

Transforma el PDR en wireframes navegables y direcciones de diseño (DS3 JSON + prompts). El output conecta con Prisma Designer o Figma Make.

DS1
Estructura

Wireframe Viability

Genera el brief de wireframe, inventario de pantallas necesarias y análisis de viabilidad del diseño. Define la estructura antes de diseñar.

Inputs
  • PDR (output de S6)
  • Restricciones técnicas
Outputs
  • Brief de wireframe
  • Inventario de pantallas
  • Viabilidad de diseño
$ejecutar DS1
DS2
Wireframes

Wireframe Generator

Genera wireframes HTML navegables que puedes revisar en el navegador. Permite validar estructura, flujo e interacciones antes de ir a alta fidelidad.

Inputs
  • Brief de wireframe (DS1)
  • Inventario de pantallas
Outputs
  • Wireframes HTML navegables
  • Flujo interactivo
$ejecutar DS2
DS3
Alta fidelidad

Design Directions

Genera 3 opciones de diseño, cada una con una dirección visual distinta. Produce un DS3 JSON con componentes Prisma y prompts para Figma Make. El output conecta con Prisma Designer (P1→P5) o se usa directo en Figma Make.

Inputs
  • Wireframes validados (DS2)
  • Catálogo Prisma (via MCP)
Outputs
  • 3 Design Directions (DS3 JSON)
  • Prompts para Figma Make
  • Input para Prisma Designer (P3→P4)
$ejecutar DS3
DS3 JSON + Prompts conectan con Prisma Designer o Figma Make

Prisma Designer — Pipeline de creación

5 skills que cubren desde la sincronización del catálogo hasta la evaluación de calidad. Requiere Prisma MCP + Figma MCP conectados.

P1
Sincronización

Sync Prisma Library

Sincroniza el catálogo de componentes Prisma leyendo directamente el archivo de Figma. Asegura que el catálogo local esté actualizado antes de validar o crear pantallas.

Inputs
  • Figma Token configurado
  • Prisma MCP conectado
Outputs
  • Catálogo de componentes actualizado
  • Propiedades y variantes sync
$/sync-prisma
P2
Búsqueda

Resolver Componente

Encuentra el componente Prisma correcto dado una descripción en lenguaje natural. Útil durante DS3 o cuando necesitas saber el nombre exacto de un componente.

Inputs
  • Descripción en lenguaje natural
  • Contexto de uso (opcional)
Outputs
  • Nombre exacto del componente
  • Propiedades disponibles
  • Variantes y estados
$/resolver-componente
P3
Validación

Validar DS3 JSON

Valida un DS3 JSON contra el catálogo de Prisma-Components y las Design Rules. Reporta errores sintácticos y de calidad antes de crear las pantallas.

Inputs
  • DS3 JSON (output de DS3)
  • Catálogo sincronizado (P1)
Outputs
  • Reporte de errores
  • Componentes no encontrados
  • Sugerencias de corrección
$/validar-ds3
P4
Creación

Crear Pantallas en Figma

Convierte el DS3 JSON validado en pantallas reales en Figma con componentes Prisma, grids, scroll, sticky headers y toda la estructura visual lista para handoff.

Inputs
  • DS3 JSON validado (P3)
  • Figma MCP conectado
Outputs
  • Pantallas en Figma
  • Componentes instanciados
  • Grids y auto-layout
$/crear-pantallas
P5
Calidad

Quality Gate

Evalúa las pantallas creadas en 6 dimensiones con scoring de 100 puntos: adherencia a Prisma, accesibilidad, consistencia, jerarquía visual, usabilidad y completitud. Mínimo 80 para handoff.

Inputs
  • Pantallas creadas (P4) o DS3 JSON
  • Screenshots (opcional)
Outputs
  • Score total /100
  • Score por dimensión
  • Recomendaciones de mejora
$/quality-gate

Chat vs Cowork vs Claude Code

Claude se puede usar de tres formas. Cada una tiene un caso de uso ideal según la complejidad de la tarea y tu perfil.

Chat

Web / Mobile

Interfaz conversacional simple. Escribes, Claude responde. Sin archivos, sin herramientas externas.

Ideal para
  • Preguntas rápidas y brainstorming
  • Redacción de textos cortos
  • Análisis de imágenes o screenshots
  • Comparar opciones de diseño
Por perfil UX
  • PD Brainstorm de features, revisar screenshots
  • UI Consultar naming, colores, spacing
  • RE Redactar guías de entrevista
  • CO Generar variantes de copy

Cowork

Desktop App

Modo avanzado con archivos, skills, plugins y MCPs. El entorno principal del Chapter UX.

Ideal para
  • Ejecutar Discovery y Diseño Agéntico
  • Usar skills y plugins del catálogo
  • Trabajar con archivos locales
  • Conectar Figma, Jira via MCP
Por perfil UX
  • PD Discovery completo, generación de PDR
  • UI DS3 a Figma, Quality Gate
  • RE Síntesis de research con archivos
  • CO Documentación masiva, guías

Claude Code

Terminal / CLI

Línea de comandos para desarrolladores. Los diseñadores no lo usan directamente, pero conviene conocerlo.

Ideal para
  • Crear y mantener plugins
  • Configurar MCPs locales
  • Automatizar tareas con scripts
  • Debug de skills y MCPs
Relevancia UX
  • PD Entender cómo se configura tu stack
  • UI Debug de Prisma MCP si algo falla
  • Solo necesario si creas plugins o MCPs

Proceso: conectar un MCP

Flujo estándar para configurar cualquier MCP que necesite el equipo.

1
Preparación

Verificar requisitos

Identifica qué MCP necesitas (Figma, Prisma, Jira, Confluence, etc.), verifica que tienes acceso a la herramienta y los permisos necesarios para generar tokens.

MCPs disponibles
  • Figma MCP — lectura/escritura de diseños
  • Prisma MCP — catálogo de componentes
  • Jira + Confluence MCP — tickets y docs
  • Microsoft Teams / SharePoint MCP
Requisitos comunes
  • Cuenta activa en la herramienta
  • Permisos para generar token/API key
  • Claude Desktop o Cowork instalado
2
Token

Generar credenciales

Ve a la configuración de la herramienta y genera un Personal Access Token o API Key con los permisos necesarios. Para MCPs de Atlassian y Microsoft, la conexión es via OAuth desde Claude Settings.

3
Conexión

Conectar en Claude

En Claude, ve a Settings → Connectors. Busca el MCP, haz clic en Connect y autoriza. Para MCPs locales (como Prisma MCP), se registran en el archivo de configuración.

#Settings → Connectors → [MCP] → Connect
4
Verificación

Verificar conexión

Prueba la conexión con un comando simple en el chat. Si funciona, el MCP está listo para usarse con skills y plugins.

$Figma: "whoami" · Prisma: "list_prisma_components" · Jira: "busca mis tickets"

Proceso: crear una skill desde cero

Cualquier diseñador del Chapter puede crear una skill para automatizar tareas repetitivas de su equipo.

1
Identificar

Detectar la oportunidad

Identifica una tarea que tu equipo repite frecuentemente y que no está cubierta por el catálogo actual. Buenas candidatas: tareas con estructura predecible, inputs claros y output definido.

Buenas candidatas
  • Generar documentos con formato fijo
  • Análisis repetitivos con criterios claros
  • Transformar un input en un output estándar
No tan buenas
  • Tareas que cambian mucho cada vez
  • Cosas que haces solo una vez
  • Tareas que requieren juicio subjetivo alto
2
Diseñar

Definir la skill

Define: trigger (cuándo se activa), inputs (qué necesita del usuario), instrucciones (paso a paso), output (formato del resultado) y criterios de calidad.

3
Construir

Escribir el SKILL.md

Crea el archivo SKILL.md con las instrucciones estructuradas. Puedes usar el Skill Creator del catálogo para asistencia guiada, o escribirlo manualmente.

$Quiero crear una skill nueva → Skill Creator se activa
4
Testear

Probar con casos reales

Ejecuta la skill con al menos 3 casos reales diferentes. Verifica que los outputs sean consistentes, completos y útiles. Ajusta las instrucciones según los resultados.

5
Publicar

Compartir con el Chapter

Usa el formulario de contribución del catálogo para proponer la skill. Incluye: nombre, descripción, dominio, perfil target y ejemplos de uso. El equipo del Chapter revisa y publica.

Proceso: Research con IA

Cómo usar Claude para potenciar el trabajo de UX Research: síntesis, análisis cualitativo y generación de artefactos.

1
Preparar

Preparar los datos de research

Recopila y anonimiza los datos antes de subirlos: transcripciones de entrevistas, resultados de surveys, notas de observación, tickets de soporte, analytics. Elimina datos personales reales.

Formatos aceptados
  • Transcripciones (.txt, .md, .docx)
  • Surveys exportados (.csv, .xlsx)
  • Screenshots y grabaciones
Anonimizar
  • Nombres → "Usuario 1", "Usuario 2"
  • Emails y teléfonos → eliminar
  • Datos financieros → rangos genéricos
2
Sintetizar

Síntesis de hallazgos

Sube los archivos a Cowork y pide a Claude que sintetice: patrones recurrentes, temas emergentes, citas representativas. Claude identifica clusters de insights que después tú validas.

$"Sintetiza estas 12 entrevistas. Identifica los 5 temas más recurrentes con citas textuales."
3
Analizar

Análisis cualitativo asistido

Pide análisis más profundos: afinidad entre hallazgos, contradicciones, segmentación por perfil de usuario, priorización por frecuencia e impacto. Claude estructura, tú interpretas.

Claude puede
  • Agrupar por afinidad temática
  • Detectar patrones cross-entrevista
  • Generar personas data-driven
Tú debes
  • Validar que los clusters tengan sentido
  • Aportar contexto de negocio
  • Tomar las decisiones de diseño
4
Generar

Artefactos de research

Genera los entregables de research: personas, journey maps, matrices de priorización, reportes de hallazgos. Si estás en el flujo agéntico, esto alimenta directamente S3 (User Needs).

$"Genera 3 personas basadas en la síntesis anterior con goals, frustraciones y contexto de uso."

Tips para ejecutar los procesos

Recomendaciones validadas por el Chapter para sacar el máximo de los procesos agénticos.

Ejecuta en orden

Los pasos se alimentan entre sí. Saltarse S2 o S3 produce un PDR incompleto. Si tienes prisa, al menos ejecuta S1, S3 y S6.

Alimenta con data real

Sube entrevistas, surveys, analytics y tickets reales en S3. Cuanto más data real le des, más preciso y útil será el output.

Valida antes de crear

Antes de crear pantallas en Figma: sync Prisma, valida el DS3 JSON, y recién entonces ejecuta /crear-pantallas. Evita retrabajar.

Usa el Quality Gate

Después de DS3, ejecuta /quality-gate para evaluar en 6 dimensiones. El score mínimo para handoff es 80/100.

Itera, no repitas

Si el resultado de un paso no te convence, ajusta el input y re-ejecuta solo ese paso. No necesitas volver a empezar todo el Discovery.

No compartas data sensible

En S3 y S5, anonimiza datos de usuarios y cifras financieras antes de subirlas. Usa datos ficticios para testing.
