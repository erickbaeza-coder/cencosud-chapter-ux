Design System Prisma

Prisma es el sistema de diseño de las plataformas App y Web que representa los valores fundamentales de profesionalismo, confianza, capacidad, crecimiento tecnológico, cultura y trabajo colaborativo. Este sistema no solo guía la coherencia visual y funcional de nuestros productos digitales, sino que también transmite la diversidad latinoamericana mediante una estética inspirada en lo colorido, abstracto y natural, con una textura multibandera que expresa dinamismo y fuerza.

Onboarding 03 / 08 — Estructura

Estructura de colores

El sistema de color tiene 3 capas jerárquicas. Cada capa resuelve un nivel distinto de abstracción.

1
Primitives

Light / Dark mode

Colores base por marca: Primario, Secundario y Terciario (10 shades cada uno). 332 variables totales. Agrupados por marca: Prisma, Jumbo, TFM, Disco, Prezunic, Metro, Prime, Vea, GBarbosa. Más Share/Cross colors (Info, Success, Warning, Error, Neutrals y Overlays) que son iguales para todas las marcas.

2
Style Tokens (Alias)

Bandera (Jumbo, Disco, etc.)

105 tokens semánticos organizados en: Text (25), Background (26), Icons (14), Border (18), Overlay (10), Gradient (12). Cada token mapea a un Primitive distinto según la bandera. Ejemplo: primary-default → Prisma/Purple/700 | Jumbo/Green-Olive/700 | TFM/Green/700 | Disco/Red-brand/700.

3
Components (Sub-Alias)

Primary / OnPrimary

153 variables a nivel componente (7-Components). Definen Primary y OnPrimary por componente: Avatar, Badge, Button, Tags, Checkbox, Chips, etc. Las variables Primary y OnPrimary se utilizan en banderas de bajo contraste donde los componentes no pasan los requerimientos de accesibilidad. Ejemplo: Vea y Metro.

Las 4 categorías de Property

El orden de construcción importa: armarlas en este orden evita la mayoría de colisiones e inconsistencias.

1

Variant — la estructura

Define las configuraciones que cambian la forma: Type, State, Size.

2

Boolean — qué es opcional

Nombra cada uno Show + Elemento. Ejemplos: Show Leading Icon, Show Badge, Show Avatar. Otros boolean válidos: Loading, Selected, Disabled, Checked, Expanded, Open, Required.

3

Instance Swap — qué es intercambiable

Expón cada icono, imagen o componente anidado que una instancia debería poder cambiar.

4

Text — qué se puede escribir

El contenido editable. Si ya existe un boolean Show correspondiente, esta property completa el par.

DS3 JSON

Formato estructurado que describe pantallas usando componentes Prisma. Es el output de DS3 (Design Directions) y el input para Prisma Designer o Figma Make.

Estructura del formato

Cada DS3 JSON contiene un array de pantallas (screens). Cada pantalla define un screen_id, screen_name, y un array de components que referencian componentes reales de Prisma con su tipo y variante. El formato es validable contra el catálogo con validate_ds3_json.

Ejemplo
// Ejemplo de un DS3 JSON minimal { "screen_id": "P01", "screen_name": "Events Feed", "components": [ { "type": "Header_app", "variant": "Default" }, { "type": "Title_section", "text": "Eventos" }, { "type": "Product Card", "variant": "Carrusel Card" } ] }

Flujo DS3 a Figma

Pipeline completo desde el output de Diseño Agéntico hasta pantallas listas en Figma con componentes reales de Prisma.

1
Input

Ejecutar DS3 → genera packets.ds3

El paso DS3 del Diseño Agéntico genera 3 design directions como DS3 JSON. Cada direction contiene las pantallas con componentes Prisma mapeados.

$/ds3-design-directions
2
Validación

validate_ds3_json → verificar antes de crear

Valida que todos los componentes referenciados existan en el catálogo de Prisma. Reporta componentes no encontrados y sugiere alternativas.

$/validar-ds3
3
Spec

create_screens_from_ds3 → generar spec enriquecida

Toma el DS3 JSON validado y genera una spec enriquecida que incluye las propiedades exactas de cada componente, sus variantes y configuraciones.

4
Prisma Designer

Crear pantallas con Prisma Designer

Desde Cowork, ejecuta el skill /crear-pantallas del plugin Prisma Designer. El plugin toma el DS3 JSON, lo conecta con el MCP de Figma y crea las pantallas directamente en tu archivo de Figma.

Prisma Designer crea
  • Frames con auto-layout
  • Componentes instanciados
  • Tokens aplicados por marca
Importante
  • Sync Prisma antes de crear
  • Valida el JSON primero
  • Revisa la estructura después
$/crear-pantallas
5
Opcional

Componentes nuevos → Figma Make

Si el DS3 incluye componentes que no existen en Prisma, se genera un prompt para Figma Make. Copia el prompt y úsalo directamente en Figma para crear el componente como diseño nuevo.

Flujo alternativo: prompts de texto

Si no tienes un DS3 JSON, puedes usar create_screens_from_prompts para describir pantallas en lenguaje natural. El MCP resuelve los componentes automáticamente y genera la spec. Ideal para prototipos rápidos o cuando el flujo agéntico no es necesario.

Tips para trabajar con Prisma

Mejores prácticas validadas por el Chapter para mantener la calidad y consistencia del sistema de diseño.

Usa tokens, no hardcodees colores

Siempre referencia tokens semánticos en vez de valores hex directos. Así los temas de cada marca se aplican automáticamente.

Consulta el catálogo antes de crear

Antes de diseñar algo nuevo, usa list_prisma_components o resolve_component para verificar que no exista ya.

Valida con resolve_component

Cuando no estás seguro del nombre exacto, describe lo que necesitas y resolve_component encontrará el match más cercano.

Respeta la jerarquía atómica

Atoms componen Molecules, Molecules componen Organisms. No saltes niveles al construir pantallas complejas.

Documenta componentes nuevos

Cada componente nuevo debe tener: descripción de uso, variantes, estados, y ejemplos. Usa create_local_component_spec para generar la doc base.

Sincroniza con sync_prisma_library

Después de cualquier cambio en Prisma-Components, ejecuta sync para que el MCP tenga el catálogo actualizado. Sin sync, los componentes nuevos no se resuelven.
